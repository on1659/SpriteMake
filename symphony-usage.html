SpriteMake local orchestration

요청, 프롬프트, 생성 결과, QA를 `output/*` batch 상태로 관리한다.

Mini-Symphony는 SpriteMake 안의 작업 보드다. 새 스프라이트 요청을 batch로 만들고, 생성 전에는 프롬프트 상태를 확인하고, PNG가 들어오면 QA가 필요한지 알려준다.

안전한 역할만 한다

이미지 API를 호출하지 않고, API key를 저장하지 않고, QA 전 PNG를 `final/`로 옮기지 않는다.

현재 보드 예시 output/SYMPHONY.md
bridge-cross generated PNG 3개, final PNG 2개
needs-refine
다음 액션 REQUESTS.md의 TBD/빈 runtime 필드 정리
refine
리포트 갱신 `-WriteReport`로 이 상태를 다시 쓴다
safe

기본 흐름

사용자는 짧게 말하고, SpriteMake는 batch 폴더와 상태 리포트로 일을 정리한다.

1

요청 받기

예: “불/얼음 드래곤 스프라이트 만들어줘.” 긴 템플릿을 먼저 요구하지 않는다.

2

batch 생성

sprite-intake.ps1가 output/{name}-{timestamp}와 기본 MD 파일을 만든다.

3

상태 스캔

symphony.ps1가 prompt, generated, final, QA 상태를 읽고 다음 액션을 제안한다.

4

외부 생성/QA

gpt-image-2 프롬프트를 외부에서 사용하고, 받은 PNG는 먼저 generated/에 둔다.

5

final 후보

QA 통과 후에만 final/ 후보가 되고, 사람이 게임 프로젝트 이동 여부를 본다.

명령어

오른쪽 버튼을 누르면 명령어를 복사한다. PowerShell에서 프로젝트 루트 기준으로 실행한다.

새 자연어 요청 받기

사용자 요청을 저장하고 batch scaffold와 `PROMPT.md`를 만든다.

.\.agents\hooks\sprite-intake.ps1 -Request "드래곤 스프라이트 그려줘. 불속성과 얼음속성 두 종류가 있어야 해."

현재 보드 보기

`output/*` batch를 스캔해서 상태와 다음 액션을 터미널에 보여준다.

.\.agents\hooks\symphony.ps1

상태 리포트 저장

`output/SYMPHONY.md`를 갱신한다. 작업 넘기기 전에 가장 자주 쓴다.

.\.agents\hooks\symphony.ps1 -WriteReport

자동화용 JSON

다른 runner나 스크립트가 batch 상태를 읽을 때 쓴다.

.\.agents\hooks\symphony.ps1 -Json

상황별 사용법

Mini-Symphony는 직접 문제를 해결하기보다, 지금 어디서 막혔는지 짚어준다.

새 스프라이트를 시작할 때

먼저 intake를 돌리고, 바로 board를 확인한다.

  • sprite-intake.ps1 실행
  • symphony.ps1로 상태 확인
  • needs-refine이면 REQUESTS/PROMPT 보강

외부 생성 전에

프롬프트가 안전하게 준비됐는지 본다.

  • prompt-ready인지 확인
  • gpt-image-2 generation target 확인
  • anchor, baseline, grid가 빠졌으면 보강

PNG를 받은 뒤

받은 파일은 바로 final이 아니다.

  • PNG를 generated/에 둔다
  • symphony.ps1로 qa-needed 확인
  • QA 통과 후에만 final/ 후보로 둔다

상태 의미

상태는 “좋다/나쁘다”가 아니라 다음 작업을 고르는 신호다.

needs-scaffold

표준 MD나 폴더가 빠졌다. `new-batch.ps1` 또는 수동 정리가 필요하다.

needs-prompt

`PROMPT.md`가 없거나 비어 있다. copy-ready prompt를 만들어야 한다.

needs-prompt-inject

`gpt-image-2` generation target이 빠졌다. `prompt-inject.ps1`를 쓴다.

needs-refine

target path, grid/cell, anchor, baseline, TBD가 남아 있다.

prompt-ready

외부 `gpt-image-2` 환경에 붙여 넣을 준비가 됐다.

qa-needed

`generated/`에 PNG가 있다. size, alpha, bbox, preview를 검수한다.

needs-regeneration

QA 실패가 기록됐다. 실패본은 `generated/`에 두고 재생성 노트를 쓴다.

mixed-review

`final/`에 PNG가 있지만 QA 실패도 있다. 통합 전 사람이 확인해야 한다.

final-review

`final/` 파일은 있지만 QA pass 기록이 더 명확해야 한다.

final-candidate

QA 통과 상태다. target path를 확인한 뒤 게임 프로젝트 이동을 검토한다.

운영 규칙

이 규칙이 SpriteMake를 이미지 생성 폴더가 아니라 게임 리소스 제작 시스템으로 유지한다.

해야 할 것

  • 짧은 요청은 먼저 `sprite-intake.ps1`로 batch화한다.
  • 외부 생성 전 `symphony.ps1`로 `prompt-ready`인지 확인한다.
  • generated PNG는 먼저 `generated/`에 둔다.
  • anchor와 Y-axis baseline/source plane을 항상 분리해서 쓴다.
  • handoff 전 `symphony.ps1 -WriteReport`로 `output/SYMPHONY.md`를 갱신한다.

하면 안 되는 것

  • 이 프로젝트에 API key를 저장하지 않는다.
  • SpriteMake가 이미지 생성 API를 직접 호출하게 만들지 않는다.
  • QA 전 PNG를 `final/`로 옮기지 않는다.
  • `gpt-image-2` 요구를 빼거나 다른 모델로 조용히 대체하지 않는다.
  • loose contact sheet를 final asset으로 취급하지 않는다.
